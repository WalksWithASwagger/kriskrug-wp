## Open: Pagely gateway cache

**This is the one outstanding item and it needs KK.**

Bare, non-cache-busted URLs can still serve pre-deploy copies from the Pagely
ARES edge (`x-gateway-cache-status: HIT`). There is no purge route exposed over
REST, and no Pagely namespace in the REST API, so this cannot be purged from
tooling in this repo.

- `/wp-json/wp/v2/users` was serving a stale 200 immediately after deploy and
  **aged out on its own during the session**; it now returns 401 bare.
- `/wp-sitemap.xml` was still serving the five-child version bare at the time of
  writing. Cache-busted it correctly returns two children.

So the fix is live and correct at origin. Until the edge entries age out or KK
purges from the Pagely dashboard, a bare request to `/wp-sitemap.xml` may still
show the archive children. `scripts/check_user_enumeration.sh` uses bare URLs
and will report the sitemap row as FAIL while that stale entry survives.

HSTS remains FAIL and is out of scope here; it belongs to #709.
