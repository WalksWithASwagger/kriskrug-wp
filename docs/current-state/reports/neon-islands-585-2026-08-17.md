## Wave B: cohesion note (read-only, feeds #403 / #423)

Live high-value pages no longer fight Aurora with a second neon theme. Remaining cohesion debt:

1. **Global preset dump.** Every page HTML still advertises `#00E5FF` via unused `theme.json` gradients/duotone. Visitors do not see a cyan island from that, but the hex is in the payload and will keep failing naive "is neon gone?" greps of live HTML. Fix: retire or recolor `aurora-cyan-teal`, `aurora-subtle`, and `aurora-duo` in a theme PR (after the 1.6.6 to 1.6.9 queue). Link: #403, #423.
2. **Services still owns a private stylesheet.** `/generative-ai-services/` uses `.kk-services-2026` with cream tokens (`#d94a1f` accent, `#efe6d2` paper). It is on-palette and not neon, but Track B polish never reaches it through `theme.json`. #420 already owns the services rethink.
3. **Double H1 / `aurora-prose`.** Architecture pages still sit in generic `page.html` chrome (theme H1 plus in-body display heading). That is #122 / #418, not a neon island.
4. **Two payload families.** Keynotes-2026 files are now paper-tokened but still `kk-overhaul` / `kk-services` class trees. Content-architecture-2026 files are the live cream primitives. Agents must prefer the architecture pack for any future live apply.
5. **Marquee teletype fallback** still names `#00E5FF`. Generated part; fix in `scripts/marquee/build.py` + `theme.json` together.

Priority order for the next polish pass: (1) retire unused neon presets in `theme.json`, (2) services private CSS → Aurora primitives (#420), (3) generic page chrome / double H1 (#122).
