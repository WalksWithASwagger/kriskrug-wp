# Aurora Revive QA — conflicting code / visual wonk (2026-07-24)

## Verdict

**Active Code Snippets are not painting the cream UI.** The wonk comes from (1) leftover **dark theme meta + wrong font preloads** in `functions.php`, (2) **Track A page packs** still carrying cyan/SaaS chrome (Contact, Services), and (3) housekeeping debt (inactive temp snippets, custom FSE `single`).

- Inventory of all 18 Code Snippets (active/inactive, CSS/theme-write flags)

Artifacts: `backup/aurora-deploy-20260724/qa/`

## Findings (ranked)

### P0 — Conflicting theme meta (Track B) → fixed in 1.4.2

Live HTML still had:

```html
<meta name="theme-color" content="#0D0D12">
<meta name="color-scheme" content="dark">
```

…while the page paints cream `#efe6d2`. That is legacy dark-Aurora conflict and can make browser chrome / native controls feel “wrong” on a light site.

Also preloaded **Inter + Clash Display** (unused) and did **not** preload Space Grotesk / DM Sans (actual faces). Network showed all five fonts loading.

**Fix:** `functions.php` → `color-scheme: light`, `theme-color: #efe6d2`, preload Space Grotesk + DM Sans. Version **1.4.2**.
